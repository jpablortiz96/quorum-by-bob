# Skill: Generate ADR (Architecture Decision Record)

## Purpose

This skill teaches Bob how to produce an ADR in the Quorum standard format. ADRs are the primary deliverable of the Quorum Council — they are designed to be committed directly to the repository and referenced by future developers.

## File Naming Convention

```
ADR-YYYY-NNN-kebab-case-title.md
```

Examples:
- `ADR-2026-001-migrate-auth-to-jwt.md`
- `ADR-2026-002-deprecate-python-etl-pipeline.md`
- `ADR-2026-003-extract-payment-microservice.md`

`NNN` is a zero-padded sequential number. Check `docs/decisions/` for the next available number.

**Save location:** `docs/decisions/` (never in `draft/`)

## ADR Template

```markdown
# ADR-[YYYY]-[NNN]: [Short Decision Title]

**Status:** Accepted | Rejected | Deferred | Superseded by ADR-YYYY-NNN
**Date:** YYYY-MM-DD
**Decision Makers:** Quorum Council
**Confidence Score:** [X]/100
**Repository:** [repo name and branch]

## Context

[Describe the architectural situation that prompted this decision. Include:
- What the current state is (cite file paths, LOC, dependency counts)
- What problem or opportunity was identified
- What constraints exist (technical, organizational, timeline)
No opinions here — only observable facts with citations.]

## Decision

[One clear sentence stating the decision made.]

[2-3 sentences expanding on what will change and what will not change.]

## Consequences

### Positive
- [Measurable or observable benefit, backed by council evidence]
- [Benefit]
- [Benefit]

### Negative
- [Cost or trade-off explicitly accepted by this decision]
- [Trade-off]

### Neutral
- [Change that is neither benefit nor cost]

| Agent | Role | Key Finding | Confidence | Source |

| The Economist | Economic Analysis | [summary] | [score]/100 | module_economics |
| The Risk Officer | Blast Radius | [summary] | [score]/100 | `file:line` |
| The Engineer | Feasibility | [summary] | [score]/100 | `file:line` |

## Council Composition

This decision was reviewed under the Quorum Council protocol (3 rounds):
- Round 1: Independent opening statements from all 6 agents
- Round 2: Cross-examination between paired opponents
- Round 3: Judicial synthesis by The Judge

All agents are required to cite specific repository evidence. Arguments without citations are flagged as inadmissible and receive zero weight.
```

## Validation Checklist

Before saving the ADR, verify:
- [ ] File named `ADR-YYYY-NNN-kebab-title.md`
- [ ] Status is one of: Accepted, Rejected, Deferred, Superseded
- [ ] Every row in Evidence Summary has a `file:line` or `commit hash`
- [ ] Consequences section has at least 1 Positive and 1 Negative
- [ ] Decision Confidence Score weights add to 100%
- [ ] File saved to `docs/decisions/` (not `draft/`)
